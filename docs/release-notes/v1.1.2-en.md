# Work Review v1.1.2

**Release date**: 2026-08-22

## Added

- WeCom intelligent-bot long connection (#147): Bot ID + Secret connects to `wss://openws.work.weixin.qq.com` without a public URL. Commands stay `/devices`, `/report`, `/generate`. Corp ID HTTP callback remains optional. Only one live connection per bot.
- Configurable assistant timeout (default 120s, 30–900) and daily-report timeout (default 300s, 60–1800). One assistant request shares an absolute deadline; the frontend cancel signal fires on timeout. Report generation aborts the background task.
- Thinking mode and output budget mapped per provider (Ollama `think`, Qwen streaming `enable_thinking`, SiliconFlow `chat_template_kwargs`, Claude thinking, Gemini thinkingBudget). Unsupported providers do not send extra fields. Claude does not enable thinking when tools are present.
- Optional WebDAV sync for portable app settings (AI, categories, appearance). Last write wins. This machine’s port, window position, autostart, and export folder stay local.

## Fixed

- Windows/Linux compact titlebar padding matches the drag layer; maximize shows a restore icon.
- Reasoning-model replies (`reasoning_content`) stream and fall back when `content` is empty; connection tests require non-empty output.
- Per-provider API keys, endpoints, and model names persist across provider switches.
- Community WeChat QR is a real PNG instead of a JPEG with a `.png` extension.

## Changed

- WeCom reconnects only when credentials change; bot commands run off the WebSocket loop so heartbeats continue.
- Assistant wrap-up reserves 5–15s from the total timeout to summarize tool results.
- Bot `/generate` uses the configured report timeout instead of a hard-coded 120s.
- Removed unused assistant question-kind code and related dead helpers.
- Security Audit no longer runs on a weekly schedule; unmaintained RustSec noise is ignored, while unsound/vulnerability advisories stay tracked.
