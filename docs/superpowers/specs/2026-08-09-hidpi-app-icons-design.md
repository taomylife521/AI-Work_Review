# 高 DPI 应用图标设计

## 目标

消除原生应用图标因重复降采样产生的软边，并为 DPR 2、DPR 3 和页面缩放保留足够的像素余量。现有应用识别、原生图标优先级、Alpha 裁边、失败兜底和圆角规则保持不变。

## 根因

- macOS 当前先通过 `sips -Z 128` 将最高 1024px 的 ICNS 压到 128px，再按 Alpha 边界裁切并缩放到 104px，形成不必要的重复采样。
- 统一输出只有 128px；时间线详情图标为 51.2 CSS px，在 DPR 2 下已经需要 102.4 个设备像素，几乎没有缩放余量，在 DPR 3 或页面放大时会发生上采样。
- `.app-icon` 后声明的 `-webkit-optimize-contrast` 覆盖 `image-rendering: auto`，不适合带抗锯齿、阴影和渐变的原生应用图标。
- macOS、Windows 和前端均会持续复用当前版本缓存；修改采样算法而不升级版本无法刷新旧图。

## 采样设计

- 统一输出透明画布从 `128×128` 升级为 `256×256`。
- 可见内容安全区从最长边 `104px` 升级为 `208px`，保持现有 `81.25%` 占比和视觉尺寸。
- macOS 使用 `sips -Z 512` 解码 ICNS，先在高分辨率输入上计算 Alpha 边界，再通过现有 Lanczos3 逻辑一次性缩放到 208px 安全区。
- Windows 继续优先读取 JUMBO HICON，并将取得的真实 RGBA 输入同一套 256/208 规范化逻辑。48px、32px 系统回退无法凭空增加细节，但仍保持当前视觉占比和兼容性。
- PNG 编码、Base64 返回格式和 Tauri `get_app_icon` 接口保持不变，不新增依赖。

## 前端渲染与缓存

- `.app-icon` 只保留 `image-rendering: auto` 和 `object-fit: contain`，删除 `-webkit-optimize-contrast`。
- 时间线继续使用稳定的 40px、44px 和 51.2px CSS 容器，不改变布局与圆角。
- macOS 磁盘缓存升级为 `v4`，Windows 磁盘缓存升级为 `v7`，前端 localStorage 升级为 `v4`；旧缓存不再读取。
- 前端持久化缓存保留最多 36 项，同时限制在 150 万字符内；超出预算的图标只保留在当前会话和后端磁盘缓存中。

## 测试与验收

- Rust 测试断言输出为 `256×256`，可见内容边界符合 208px 安全区。
- Rust 测试断言 macOS 输入上限为 512，并断言 macOS/Windows 缓存版本联动升级。
- JavaScript 测试断言前端缓存为 v4，且全局图标样式不再包含 `-webkit-optimize-contrast`。
- JavaScript 集成测试使用大 Base64 图标验证持久化内容不超过 150 万字符。
- 运行图标专项 Node/Rust 测试、前端完整测试、生产构建和 `git diff --check`。
- 在 DPR 2 与 DPR 3 下检查时间线图标的固有尺寸和截图像素，确认图片非空、无上采样、无布局偏移。

## 范围边界

- 不为单个品牌维护 SVG 或位图覆盖表。
- 不修改应用名称匹配、安装器判断和分类逻辑。
- 不删除用户缓存文件；通过版本升级自然失效。
- 不修改用户正在进行的语义记忆相关代码。
