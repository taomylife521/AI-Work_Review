# Issue #140 隐藏桌宠通知窗口修复设计

**日期：** 2026-08-03  
**状态：** 已经用户确认  
**选择方案：** 方案 1 — 恢复跟进通知展开尺寸的优先级

## 1. 问题背景

启用“隐藏桌宠本体”后，普通状态下桌宠原生窗口会收缩为仅保留通知区域的紧凑高度。当“接上次继续”跟进通知出现时，前端虽然请求将原生窗口切换为展开状态，但 Rust 侧尺寸计算仍然无条件采用隐藏本体高度。

默认缩放比例为 `0.9` 时：

- 跟进通知正常展开尺寸约为 `342 × 396px`；
- 隐藏本体后的错误尺寸约为 `342 × 99px`；
- 卡片在扣除上下边距后只剩约 `83px` 可用高度。

这会导致通知内容被原生 WebView 窗口边界裁剪、摘要滚动区域被压缩，以及底部操作按钮不可见。

## 2. 根因

`avatar_window_size(scale, expanded, body_hidden)` 当前先根据 `expanded` 选择普通或展开尺寸，随后又在 `body_hidden` 为真时无条件把高度替换为 `AVATAR_WINDOW_BODY_HIDDEN_BASE_HEIGHT`。

因此组合状态：

```text
expanded = true
body_hidden = true
```

错误地得到“展开宽度 + 隐藏本体紧凑高度”，破坏了历史版本中跟进通知出现时动态扩展窗口的契约。

## 3. 目标行为

窗口尺寸状态优先级调整为：

1. 存在跟进通知、窗口处于展开状态时，始终使用展开尺寸；
2. 仅在非展开状态且隐藏桌宠本体时，使用隐藏本体紧凑高度；
3. 非展开且显示桌宠本体时，使用普通桌宠窗口尺寸。

预期状态矩阵：

```text
expanded=false, body_hidden=false
→ 普通桌宠窗口：276 × 248 基准尺寸

expanded=false, body_hidden=true
→ 隐藏本体紧凑窗口：276 × 110 基准尺寸

expanded=true, body_hidden=false
→ 跟进通知展开窗口：380 × 440 基准尺寸

expanded=true, body_hidden=true
→ 跟进通知展开窗口：380 × 440 基准尺寸
```

所有尺寸继续应用现有桌宠缩放比例。

## 4. 实现设计

仅修改 `avatar_engine.rs` 中的尺寸组合规则，使 `expanded` 对高度具有最高优先级：

```rust
let effective_height = if expanded {
    AVATAR_WINDOW_EXPANDED_BASE_HEIGHT
} else if body_hidden {
    AVATAR_WINDOW_BODY_HIDDEN_BASE_HEIGHT
} else {
    AVATAR_WINDOW_BASE_HEIGHT
};
```

宽度继续沿用现有规则：展开状态使用展开宽度，非展开状态使用普通宽度。

不修改前端跟进卡片结构。当前 `AvatarWindow.svelte` 已能在跟进通知出现和消失时正确调用 `set_avatar_window_expanded`，`AvatarFollowupCard.svelte` 在恢复正常原生窗口高度后已有足够空间展示标题、摘要和全部操作按钮。

## 5. 测试设计

遵循测试驱动流程，先增加能够复现回归的 Rust 单元测试，并确认测试在修改生产代码前按预期失败。

### 5.1 核心回归测试

验证隐藏桌宠本体时，展开通知仍然采用完整展开尺寸：

```rust
avatar_window_size(0.9, true, true)
```

期望结果：

```text
342 × 396px
```

该测试在当前错误实现下会得到约 `342 × 99px`，从而证明能够捕获 Issue #140。

### 5.2 状态矩阵测试

覆盖以下四种组合：

- 普通、显示本体；
- 普通、隐藏本体；
- 展开、显示本体；
- 展开、隐藏本体。

重点保证隐藏本体只影响非展开状态。

### 5.3 缩放边界

现有缩放测试继续覆盖 `0.7`、`0.9` 和 `1.3`。新增测试至少使用默认缩放 `0.9`，并确认尺寸仍经过统一缩放计算，不引入独立的未缩放分支。

## 6. 验证范围

实现后执行：

1. `avatar_engine` 相关 Rust 单元测试；
2. `cargo test` 或仓库已有的等价 Rust 测试命令，单次最大超时 60 秒；
3. 桌宠窗口相关 Node 测试；
4. 项目格式化与静态检查；
5. 构建验证；
6. 独立代码审查。

如果全量 Rust 测试因环境或编译耗时超过 60 秒，将明确记录超时，并继续执行能够完成的定向测试和静态验证，不把超时描述为测试通过。

## 7. 非目标

本次修复不包含：

- 重构 `AvatarFollowupCard.svelte` 的滚动结构；
- 调整通知卡片视觉样式或按钮排列；
- 修改普通通知气泡的截断策略；
- 增大隐藏桌宠在无通知状态下的常驻窗口；
- 修改跟进通知触发条件或业务动作；
- 新增依赖；
- 修改发布版本号或发布说明。

## 8. 风险与回退

修复只改变 `expanded=true && body_hidden=true` 时的窗口高度。其他三个状态组合保持原有行为，因此影响面较小。

主要风险是展开窗口靠近屏幕边缘时需要重新钳制位置；现有 `apply_avatar_window_expansion` 已在调整尺寸后调用窗口位置钳制逻辑，本次不改变该流程。

若出现回归，可回退尺寸优先级修改和对应测试，不涉及数据迁移或配置格式变化。
